> **一句话定位**：类型标注是"工业代码"和"一次性脚本"最显眼的分界线。它不改变运行时，却能让 bug 在写代码时就被工具抓住、让 IDE 补全和重构变准。

## 0. 先跑起来

```python
# 07_typing_basic_demo.py
from __future__ import annotations   # ① 让所有标注"延迟求值"，前向引用不用引号
from typing import Callable

# ── 1. 基础类型标注 ──
def scale(x: float, factor: int) -> float:   # 参数:类型, 返回值:类型
    return x * factor

name: str = "gpt"                    # 变量也可以标注
counts: list[int] = [1, 2, 3]        # 泛型容器：list 里装 int
table: dict[str, int] = {"a": 1}     # dict 的键/值类型
point: tuple[float, float] = (1.0, 2.0)

# ── 2. 可选值与联合类型 ──
def find_token(s: str, vocab: dict[str, int]) -> int | None:   # 可能返回 None
    return vocab.get(s)              # get 找不到返回 None

def process(x: int | str) -> str:    # x 可以是 int 或 str
    return str(x)

# ── 3. Callable：把"函数"也标注类型 ──
def apply(fn: Callable[[int, int], int], a: int, b: int) -> int:
    return fn(a, b)                  # fn 是"接收两个 int、返回 int"的函数

def add(x: int, y: int) -> int: return x + y
print(apply(add, 1, 2))              # 3

# ── 4. 类型标注不影响运行时 ──
def only_int(x: int) -> int:
    return x
print(only_int("你好"))               # 照样运行！类型只是"提示"，Python 不强制
```

运行：`python 07_typing_basic_demo.py`。

**再装 mypy 跑一次静态检查**：

```powershell
pip install mypy          # 或 uv tool install mypy
mypy 07_typing_basic_demo.py
```

你会看到 mypy 报出 `only_int("你好")` 的类型错误——**这就是"运行时不管、静态检查管"的含义**。

## 1. 一句话直觉

> **类型标注 = 给代码加"说明书"，mypy/pyright = 读说明书挑毛病的质检员。**

类比：类型标注像工厂零件图上的**尺寸公差标注**——机器（Python 运行时）其实不看公差也能装，但质检员（mypy）会拿着图纸检查"这里说要 int，你给了 str，不合格"。**写代码时标类型，就是给未来的自己（和同事、和 AI 工具）留一份能自动检查的意图说明书。**

## 2. 核心原理

### 2.1 渐进式类型（gradual typing）

Python 的类型系统是**渐进式**的：你可以**只标注一部分**代码，剩下的不管。mypy 默认只检查"你标注了的地方"，未标注的当作 `Any`（跳过）。

```python
def typed(x: int) -> int:      # 已标注 → 会被检查
    return x * 2

def untyped(x):                # 未标注 → mypy 默认不管（视作 Any）
    return x * 2
```

**工业落地路径**：不用一次性全标注，而是**从核心接口开始**（你项目的 `Backend` 抽象、`Config`、公共函数），逐步扩大覆盖率。这正是我们要对你项目做的事。

### 2.2 `from __future__ import annotations` 为什么放在第一行

默认情况下，函数标注在**定义时立即求值**。这会导致两个麻烦：

```python
# 没有 future import：标注立即求值，类还没定义就引用会炸
def f() -> Model:      # NameError: name 'Model' is not defined（如果 Model 定义在后面）
    ...

# 有 future import：标注变成"字符串"，延迟到真正需要时才求值
from __future__ import annotations
def f() -> Model:      # ✅ 不报错，Model 可以后定义
    ...
```

**约定：每个新文件第一行（docstring 之后）写 `from __future__ import annotations`**。

> ⏱ **Python 3.14 更新**：3.14 起 [PEP 649](https://peps.python.org/pep-0649/) 让注解**默认惰性求值**（用描述符机制，保留真实对象而非转字符串），所以 3.14+ 里这个 future import 基本**不再必需**（仍兼容保留）。本笔记按你 venv 的 **3.13** 教学，故仍写它；升级到 3.14 后可逐步移除。

### 2.3 现代联合类型写法：`X | Y` 取代 `Optional[X]`

| 旧写法 | 新写法（3.10+） | 含义 |
|--------|----------------|------|
| `Optional[int]` | `int | None` | 可能是 int 或 None |
| `Union[int, str]` | `int | str` | int 或 str |

```python
def find(s: str, vocab: dict[str, int]) -> int | None:   # 推荐
    return vocab.get(s)
```

**为什么推荐新写法**：`X | Y` 直观、无需 import `Optional`/`Union`、和 PEP 604 的 `isinstance` 语法一致。

### 2.4 容器泛型（内建小写形式）

Python 3.9+ 起，直接用内建类型做泛型，**不需要**从 `typing` import `List/Dict/Tuple`：

```python
# 推荐（3.9+）：
xs: list[int] = [1, 2, 3]
d: dict[str, int] = {"a": 1}
p: tuple[float, float] = (1.0, 2.0)
s: set[str] = {"a", "b"}

# 旧式（不推荐再写）：
from typing import List, Dict, Tuple
xs: List[int] = [1, 2, 3]
```

### 2.5 `Callable`：函数的类型

```python
from typing import Callable
# 接收两个 int、返回 int 的函数
op: Callable[[int, int], int] = lambda a, b: a + b
```

- `Callable[[参数类型...], 返回类型]`：方括号里第一个是参数类型元组，第二个是返回类型。
- `Callable[..., int]`：`...` 表示"参数任意"。

> 你 `bindings.cpp` 里 `torch::Tensor vector_add(torch::Tensor, torch::Tensor)` 就是 C++ 侧的"函数签名"，和 Python 的 `Callable[[Tensor, Tensor], Tensor]` 是同一个思想。

## 3. 深入细节：给你的 `backend.py` 完整加类型

这是本篇的**实战核心**。对比你现在的代码和加了类型后的版本：

```python
# ── 现在（backend.py 节选）：抽象有类型、实现裸奔 ──
class Backend(ABC):
    @abstractmethod
    def rmsnorm(self, x: torch.Tensor, weight: torch.Tensor, eps: float = 1e-6) -> torch.Tensor: ...

class TorchBackend(Backend):
    def rmsnorm(self, x, weight, eps=1e-6):   # ❌ 实现没有类型
        ...

# ── 加类型后 ──
from __future__ import annotations

class Backend(ABC):
    @abstractmethod
    def rmsnorm(self, x: torch.Tensor, weight: torch.Tensor, eps: float = 1e-6) -> torch.Tensor: ...

    @abstractmethod
    def attention(self, q: torch.Tensor, k: torch.Tensor, v: torch.Tensor, *, causal: bool = True) -> torch.Tensor: ...

    @abstractmethod
    def fused_ffn(self, x: torch.Tensor, w_gate: torch.Tensor, w_up: torch.Tensor, w_down: torch.Tensor) -> torch.Tensor: ...

class TorchBackend(Backend):
    def rmsnorm(self, x: torch.Tensor, weight: torch.Tensor, eps: float = 1e-6) -> torch.Tensor:
        in_dtype = x.dtype
        x = x.float()
        variance = x.pow(2).mean(dim=-1, keepdim=True)
        x_norm = x * torch.rsqrt(variance + eps)
        return (x_norm.to(in_dtype)) * weight

    def attention(self, q: torch.Tensor, k: torch.Tensor, v: torch.Tensor, *, causal: bool = True) -> torch.Tensor:
        ...
    def fused_ffn(self, x: torch.Tensor, w_gate: torch.Tensor, w_up: torch.Tensor, w_down: torch.Tensor) -> torch.Tensor:
        ...
```

**关键点**：
1. **子类方法的签名要和父类一致**（参数类型、返回类型）。mypy 会检查 override 是否合规（父类说返回 `Tensor`，子类返回 `Tensor` ✅）。
2. **`*` 后面的 `causal` 是 keyword-only**（你原来已经写了 `*`，很好，这是工业好习惯：强制调用者写清楚 `causal=True`，避免位置传参误传）。
3. 加了 `dtype` 这类 torch 类型，`x.dtype` 是 `torch.dtype`——但这里我们只需在函数边界标 `Tensor`，内部细节让 torch 的 stub 管。

**运行检查**：

```powershell
mypy 推理引擎/engine/backend.py
```

### 3.1 类型标注能帮你抓到什么真实 bug？

你 `model.py` 里有：

```python
def get_batch(block_size, batch_size, device):   # ❌ 无类型
    ix = torch.randint(len(data) - 1 - block_size, (batch_size,))
    ...
```

`data` 是全局变量（只在 `__main__` 里赋值），`get_batch` 无类型、依赖隐式全局。加了类型后，你会被迫思考：`data` 从哪来？`block_size` 是 int 吗？`device` 是什么？——**类型标注强迫你把"隐式依赖"变成"显式参数"**：

```python
def get_batch(data: torch.Tensor, block_size: int, batch_size: int, device: torch.device | str) -> tuple[torch.Tensor, torch.Tensor]:
    ...
```

## 5. 自测题

**Q1（概念）**：`from __future__ import annotations` 解决的核心问题是什么？为什么它不影响运行时？

**Q2（应用）**：写出下面函数的完整类型标注（含返回类型）：

```python
def merge(a, b):
    result = {}
    for k in a:
        result[k] = a[k]
    for k in b:
        result[k] = b[k]
    return result
```

**Q3（思考）**：为什么"子类实现方法的签名必须和父类抽象方法一致"这件事，mypy 能帮你检查？它体现了类型系统对"接口契约"的什么保护作用？

<details>
<summary>点击展开答案</summary>

**A1**：解决"前向引用"和"标注立即求值"的问题——把标注从"定义时求值的对象"变成"延迟求值的字符串"，这样函数可以引用**后面才定义**的类型（如类自己），且定义类时标注不会真的去构造那些类型对象，也不产生运行时开销。它不影响运行时，是因为类型标注本来就被 Python 解释器**忽略**（存进 `__annotations__` 字典但不用来执行），future import 只是改变"标注何时被求值"。

**A2**：
```python
from __future__ import annotations
def merge(a: dict[str, int], b: dict[str, int]) -> dict[str, int]:
    result: dict[str, int] = {}
    for k in a: result[k] = a[k]
    for k in b: result[k] = b[k]
    return result
```

**A3**：mypy 在做 **override 检查**（override checking）：子类方法被识别为"覆写父类方法"，mypy 比较两者签名，若参数类型收窄、返回类型变宽等违反**里氏替换原则（LSP）**，就报错。这保护了"接口契约"——任何"拿父类引用调用"的代码，换任何子类实现都保证类型安全。你 `Backend`/`TorchBackend` 正是这个模式的受益者：上层模型只认 `Backend`，换任何后端都安全。
</details>
