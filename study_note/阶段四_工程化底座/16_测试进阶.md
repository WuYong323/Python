## 0. 先跑起来

```python
# test_demo.py —— 演示 fixture / parametrize / monkeypatch / tmp_path
import pytest

# ── 1. fixture：复用的"准备/清理"逻辑 ──
@pytest.fixture
def device():
    import torch
    return "cuda" if torch.cuda.is_available() else "cpu"

@pytest.fixture
def backend(device):
    from inference_engine.engine.backend import TorchBackend
    return TorchBackend()                    # 每个测试拿到独立实例

def test_rmsnorm_shape(backend, device):     # 直接用 fixture，不用自己建
    import torch
    x = torch.randn(2, 8, 64, device=device)
    w = torch.ones(64, device=device)
    assert backend.rmsnorm(x, w).shape == x.shape

# ── 2. parametrize：一次写，多组数据跑 ──
@pytest.mark.parametrize("shape", [(2, 8, 64), (1, 128, 512), (4, 1, 4096)])
def test_rmsnorm_shapes(backend, device, shape):
    import torch
    x = torch.randn(*shape, device=device)
    w = torch.ones(shape[-1], device=device)
    assert backend.rmsnorm(x, w).shape == shape

# ── 3. monkeypatch：临时替换环境/外部依赖 ──
def test_no_cuda_path(monkeypatch):
    import torch
    monkeypatch.setattr(torch.cuda, "is_available", lambda: False)  # 假装没有 GPU
    assert torch.cuda.is_available() is False                       # 隔离测试环境

# ── 4. tmp_path：临时文件系统，自动清理 ──
def test_save_load(tmp_path):
    p = tmp_path / "ckpt.pt"
    import torch
    torch.save({"x": 1}, p)
    assert torch.load(p, weights_only=True)["x"] == 1   # 用临时目录，不污染仓库
```

运行：`pytest test_demo.py -v`。

## 1. 一句话直觉

> **fixture 是"公共准备工作台"（每个测试都用同一套准备），mock/monkeypatch 是"替身演员"（把外部依赖换成假的，隔离测试），hypothesis 是"自动出题机器"（自动生成大量输入来验证性质），coverage 是"覆盖率体检单"（看哪些代码没被测到）。**

类比：测试像"质检流水线"——fixture 是固定好参数的测试台，parametrize 是"同一条流水线换不同零件各测一遍"，mock 是把"还没到货的真零件"换成"尺寸一样的假零件"先测，hypothesis 是"自动随机抽检"，coverage 是"记录哪些工序没被抽检过"。

## 2. 核心原理

### 2.1 fixture：复用 + 清理

```python
@pytest.fixture
def engine():
    e = Engine()        # 准备
    yield e             # 交给测试用
    e.cleanup()         # 测试结束后清理（yield 之后是 teardown）
```

**关键点**：
- `yield` 前 = setup，`yield` 后 = teardown（测试结束自动执行，即使测试失败）。
- fixture 可以**依赖别的 fixture**（`backend` 依赖 `device`）。
- **scope** 控制复用范围：`function`（每个测试新造，默认）/ `module` / `session`（整个测试会话共享一次）。

```python
@pytest.fixture(scope="session")
def model():                 # 整个测试会话只加载一次大模型（省时间）
    return load_model()
```

> **你的项目最该加的 fixture**：`device`（你每个测试都手写 `"cuda" if torch.cuda.is_available() else "cpu"`）、`backend`、以及一个 `session` 级别的 `model`（加载模型很慢，会话级共享一次）。

### 2.2 你已经会的 `parametrize`，升个级

你 `test_backend.py` 已经用了 `@pytest.mark.parametrize("shape", [...])`——很好。升级点：

```python
# 参数化多个参数（笛卡尔积）
@pytest.mark.parametrize("shape", [(2,8,64), (1,128,512)])
@pytest.mark.parametrize("eps", [1e-5, 1e-6])
def test_rmsnorm(backend, device, shape, eps):   # shape × eps 所有组合都测
    ...

# 给参数起可读的 id
@pytest.mark.parametrize("dtype", [torch.float32, torch.float16], ids=["fp32", "fp16"])
def test_dtype(dtype): ...
```

### 2.3 mock / monkeypatch：隔离外部依赖

**为什么要 mock**：测试要**快、可重复、不依赖外部**。你不想每次测试真去下载模型、真读 CUDA、真连网络。

```python
# monkeypatch：替换属性/环境变量/字典项
def test_device_selection(monkeypatch):
    monkeypatch.setenv("CUDA_VISIBLE_DEVICES", "-1")   # 屏蔽 GPU
    monkeypatch.setattr(module, "load_from_s3", fake_load)  # 替换网络函数
```

```python
# unittest.mock：更精细的 mock（记录调用、指定返回值）
from unittest.mock import MagicMock, patch

@patch("inference_engine.engine.backend.torch.cuda.is_available", return_value=False)
def test_cpu_fallback(mock_cuda):
    # torch.cuda.is_available() 在这里恒返回 False
    ...
    mock_cuda.assert_called_once()   # 还能断言"被调用了"
```

**你的项目场景**：`regression_test.py` 里 `torch.load("checkpoint.pt")` 依赖真实的 checkpoint 文件——测试就**绑死了一个大文件**。用 `monkeypatch`/fixture 生成小模型权重，测试就**自包含、可移植**（CI 里没有你的 checkpoint 也能跑）。

### 2.4 hypothesis：自动化性质测试

你 `test_rope.py` 手写了"相对距离不变性""模长不变"——这本质就是**性质测试**（property-based test）：不测"某个具体输入对不对"，而测"对所有输入，某个性质都成立"。`hypothesis` 把它自动化：

```python
from hypothesis import given, strategies as st

@given(v=st.lists(st.floats(-10, 10), min_size=1, max_size=100))
def test_norm_preserved(v):       # 自动生成成千上万组 v 来验证"性质"
    import math
    assert math.isclose(sum(x*x for x in v) ** 0.5, norm(v))
```

**核心思想**：你只描述"性质"和"输入的形状"，hypothesis 自动生成海量输入（含边界、极端值）来找反例。它常能抓到你手写测试永远想不到的 corner case。

> 你的 `test_rope.py` 三个性质测试，用 hypothesis 改写后，会在**随机位置、随机维度、随机向量**上自动验证，覆盖远超手写的几个点。这是它"手写性质测试"的工业级升级。

### 2.5 coverage：量化覆盖，但别迷信

```powershell
pytest --cov=inference_engine --cov-report=term-missing tests/
```

输出每个文件的**行覆盖率**，`term-missing` 列出**哪些行没被测到**。

**正确心态**：覆盖率是"下限检查"（低于某值=严重欠测），**不是目标**（100% 覆盖不代表没 bug）。真正有价值的是"**关键路径 + 边界条件**被覆盖"，而不是盲目堆到 100%。

## 3. 深入细节：修好你的 `regression_test.py`

你现在的 `regression_test.py`（全文见第 0 节前我读的代码）有几个**硬伤**：

1. **它是"脚本"不是"测试"**：`ckpt=torch.load(...)`、`model=...`、`print(...)` 全写在**模块顶层**——pytest 收集测试时会**立即执行**这些（还没跑任何 test 函数就加载模型了），CI 里没 checkpoint 直接崩。
2. **`torch.load` 没 `weights_only`**（第 09 篇的安全问题）。
3. **`print("BASELINE OUTPUT...")` 靠人眼看**，不是自动断言——不是"测试"，是"演示"。

**改造：把它变成真正的"黄金输出回归测试"**：

```python
# tests/test_regression.py —— 正确的回归测试
import torch
import pytest

@pytest.fixture(scope="session")
def model():
    from inference_engine.engine.model import GPT, Config
    ckpt = torch.load("checkpoint.pt", map_location="cpu", weights_only=True)  # ✅ 安全
    m = GPT(Config(**ckpt["model_args"]))
    m.load_state_dict(ckpt["model"])
    m.eval()
    return m

def test_generate_matches_golden(model):
    ctx = torch.zeros((1, 1), dtype=torch.long)
    with torch.no_grad():
        out = model.generate(ctx, max_new_tokens=100)
    got = out[0].tolist()[:20]
    # 黄金输出：改动算子前先记录一次，之后每次都要一致
    golden = [0, 44, 44, 549, 366, 888, 532, 644, 3422, 4298,
              104, 1090, 1798, 4294, 3912, 112, 4295, 0, 44, 44]
    assert got == golden, f"输出变了！got={got}"
```

**什么是"黄金输出回归测试"**：把"当前正确实现的输出"固化成一个常量（golden），之后每次改代码，如果输出变了就报警。**用途**：你重构 `backend.py`、优化 kernel 时，这个测试保证"结果没被改坏"——这正是"回归"二字的含义。你的 `regression_test.py` 里那段 `BASELINE OUTPUT: [0, 44, ...]` 注释，**就是黄金输出**，只是没做成自动断言。

## 5. 自测题

**Q1（概念）**：fixture 的 `yield` 前后分别是什么？为什么"teardown 在 `yield` 后"能保证测试失败时也会清理？

**Q2（应用）**：写一个 fixture，作用是"为测试提供一个临时的小型随机模型权重 + 对应 Config"，并在测试里用它验证 `generate` 不报错且输出形状正确。

**Q3（思考）**：为什么"黄金输出回归测试"对算子重构（如把 Python attention 换成 CUDA/Triton kernel）特别有价值？它抓住了重构的什么本质要求？

<details>
<summary>点击展开答案</summary>

**A1**：`yield` 前是 **setup**（准备资源），`yield` 后是 **teardown**（清理资源）。pytest 把 fixture 包装进 `try/finally`，所以即使测试体抛异常，`yield` 之后的 teardown 也会在 `finally` 里执行——保证资源（文件、连接、显存、模型）一定被清理，不因失败而泄漏。

**A2**（示例）：
```python
@pytest.fixture
def tiny_model():
    import torch
    from inference_engine.engine.model import GPT, Config
    cfg = Config(vocab_size=64, block_size=32, n_embd=64, n_head=4,
                 n_layer=2, dropout=0.0)
    m = GPT(cfg, TorchBackend())
    return m, cfg

def test_generate_shape(tiny_model):
    model, cfg = tiny_model
    ctx = torch.zeros((1, 1), dtype=torch.long)
    with torch.no_grad():
        out = model.generate(ctx, max_new_tokens=10)
    assert out.shape == (1, 11)   # 1 个初始 token + 10 个新 token
```

**A3**：算子重构的本质要求是"**行为等价**"——换了实现（Python → CUDA/Triton），**结果必须和原来一致**。黄金输出回归测试用"固化下来的正确输出"作为**客观判据**，自动检测"新算子是否和旧算子产出完全相同"。它抓住了重构的命门：**你可以改内部实现，但不能改变可观测行为**；一旦输出漂移（哪怕数值误差），测试立即报警，让你在引入 bug 的第一时间发现，而不是等模型线上出幻觉才察觉。
</details>
