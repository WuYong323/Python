## 0. 重构路线图（按依赖顺序，别跳）

重构不是一次改完，而是**按依赖顺序分 6 步**，每步改完都要 `pytest` 全绿再下一步：

```
Step 1  工程骨架：建 pyproject.toml + 重命名包 → 能 pip install -e .
Step 2  类型与质量：加类型标注 + ruff/mypy 配置 → 静态检查零错
Step 3  配置与日志：Config 换 pydantic + print 换 logging
Step 4  测试补齐：fixture + 黄金回归 + 覆盖率
Step 5  设计与算子：Backend 工厂 + register_fake + torch.compile
Step 6  serving：异步调度器 + 限流 + 性能对标
```

> ⚠️ 原则：**每步小步走、每步可回滚、每步测试绿**。别想着"一次性全重构完"——那是失控的开始。

## 1. Step 1：工程骨架（半天）

**目标**：从"一堆脚本"变成"可安装的包"。

```powershell
cd PythonProject1
# 1. 建 pyproject.toml（第 15 篇模板）
# 2. 重命名 推理引擎 → src/inference_engine/
# 3. 建 src/inference_engine/__init__.py、engine/__init__.py、cli.py
uv pip install -e .          # 可编辑安装
uv run pytest tests/          # 确认导入路径改对、测试仍绿
```

**关键动作**：
- 全局替换 `from 推理引擎.engine.X` → `from inference_engine.engine.X`。
- 把 `model.py` 的 `if __name__ == "__main__"` 里的交互式 `input()` 改成 `cli.py` 的 argparse（第 15 篇）。

## 2. Step 2：类型与质量（半天）

**目标**：静态检查零错。

```toml
# pyproject.toml 里合并（第 08、10 篇）
[tool.mypy]
strict = true

[tool.ruff]
line-length = 100
[tool.ruff.lint]
select = ["E", "F", "I", "B", "UP", "SIM", "N", "S"]
```

```powershell
ruff format . && ruff check --fix .
mypy src/inference_engine/
```

**关键动作**：
- 补齐所有函数类型标注（第 07 篇，先 `backend.py`、`PagedAttention.py`）。
- `torch.load` 全加 `weights_only=True`（第 09 篇）。

## 3. Step 3：配置与日志（半天）

**目标**：消灭魔法数字 + print。

- `Config` 换 pydantic（第 18 篇），`assert n_embd % n_head == 0` 移进 `@model_validator`。
- 建 `SamplingConfig`（收编 `temperature=0.8`、`top_k=200`）、`InitConfig`（收编 `std=0.02`）。
- `print` 换 `logging`/`structlog`（第 09 篇），每个模块 `getLogger(__name__)`。

## 4. Step 4：测试补齐（半天）

**目标**：测试金字塔 + 黄金回归。

- 建 `tests/conftest.py`：`device`、`backend` fixture（第 16 篇）。
- 把 `regression_test.py` 改成 `test_regression.py`（fixture + 黄金输出断言，第 16 篇）。
- `pytest --cov` 查覆盖率，补核心算子测试。

## 5. Step 5：设计与算子（1 天）

**目标**：可扩展设计 + 算子工业级。

- `Backend` 加工厂/注册表（第 17 篇），`model.py` 的 if/elif 换成工厂。
- 给 `cuda_ext` 的算子补 `register_fake`（第 20 篇）。
- `TorchBackend` 的算子加 `torch.compile(mode="reduce-overhead")`（第 21 篇）。
- `PagedAttention.py` 升级成生产级 `BlockManager`（第 22 篇：set + 引用计数 + preempt + copy-on-write）。

## 6. Step 6：serving（1 天）

**目标**：能上生产的异步服务。

- `AsyncEngine`（asyncio.to_thread 包 forward）+ `ServingScheduler`（Semaphore 限流）（第 23 篇）。
- 接 `BlockManager`（完成即释放、新请求即分配）。
- structlog 按 `request_id` 追踪。
- 用 roofline/cost model 对标，写进 README。

## 7. 面试要点：怎么讲你的项目

重构完成后，你有一个**完整闭环**的 AI Infra 作品。面试时的叙事结构（STAR 法则）：

### 7.1 一句话定位

> "我独立实现了一个 LLM 推理引擎，覆盖从算子（CUDA/Triton）到 serving（异步调度 + PagedAttention）的完整链路，并用工业级工程规范（类型/测试/打包/性能对标）保证质量。"

### 7.2 三个必讲的亮点（按"深度"递进）

| 亮点 | 你做了什么 | 面试官看到的能力 |
|------|-----------|-----------------|
| **算子下沉** | 写了 CUDA/Triton kernel（RMSNorm、attention、matmul），用 pybind11 + `TORCH_LIBRARY` 接入 torch | 高性能计算、C++/CUDA 能力 |
| **显存管理** | 实现 PagedAttention（块管理 + 引用计数 + 抢占），解决 KV cache 碎片 | 系统设计、内存管理、理解 vLLM 原理 |
| **工程底座** | 全项目类型标注 + mypy strict + ruff + pytest 黄金回归 + pydantic 配置 + 打包 | 工程纪律、可维护性、工业素养 |

### 7.3 高频面试题（现在你应该能答）

1. **"GIL 是什么？为什么推理服务用 asyncio 而不是多线程？"**（第 11、12 篇）
2. **"PagedAttention 和普通 KV cache 的区别？为什么能提升吞吐？"**（第 22 篇）
3. **"torch.compile 的原理？什么时候该手写 kernel？"**（第 21 篇）
4. **"`view` 和 `reshape` 的区别？`contiguous` 为什么有开销？"**（第 19 篇）
5. **"自定义算子怎么保证 meta 安全和 autograd 正确？"**（第 20 篇）
6. **"你的引擎怎么对标性能？roofline 能告诉你什么？"**（第 23 篇）
7. **"`torch.load` 为什么要 `weights_only=True`？"**（第 09 篇）

### 7.4 简历项目的写法建议

```
项目：LLM 推理引擎（个人项目）
- 独立实现 GPT/Llama 架构推理引擎，支持 RoPE/RMSNorm/SwiGLU/权重绑定
- 用 CUDA/Triton 编写并接入自定义算子（pybind11 + TORCH_LIBRARY + register_fake）
- 实现 PagedAttention 显存管理（块式分配 + 引用计数 + 抢占换出），对比连续分配降低碎片
- 用 asyncio 搭建异步 serving 调度（continuous batching + 信号量限流）
- 全项目 mypy strict + ruff + pytest 黄金回归测试 + pydantic 配置，可 pip install
```
