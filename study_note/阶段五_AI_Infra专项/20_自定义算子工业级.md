## 0. 先跑起来

```python
# 20_custom_op_demo.py
import torch

# ── 1. 用 torch.library 注册一个纯 Python 自定义算子 ──
# 定义一个函数
def my_add(x: torch.Tensor, y: torch.Tensor) -> torch.Tensor:
    return x + y

# 注册进 dispatcher（较新的 API，等价于 C++ 的 TORCH_LIBRARY）
torch.library.define("mylib::add", "(Tensor x, Tensor y) -> Tensor")
torch.library.impl("mylib::add", "CPU", my_add)
torch.library.impl("mylib::add", "CUDA", my_add)   # 简化：同样实现

# 关键：注册 fake 实现（给 meta tensor 用，torch.compile 需要！）
@torch.library.register_fake("mylib::add")
def _(x, y):
    return torch.empty_like(x)      # 只返回"形状对"的空张量，不真算

# 调用
a, b = torch.randn(3, 4), torch.randn(3, 4)
print(torch.ops.mylib.add(a, b))

# 用 meta tensor 验证"不真算也能推导形状"（torch.compile 的核心能力）
meta_a = torch.randn(3, 4, device="meta")
print(torch.ops.mylib.add(meta_a, meta_a).shape)   # torch.Size([3, 4])

# ── 2. 自定义 autograd：torch.autograd.Function ──
class ReLUSquared(torch.autograd.Function):
    @staticmethod
    def forward(ctx, x):                  # 前向：记录需要的东西到 ctx
        ctx.save_for_backward(x)
        return x.clamp(min=0) ** 2        # relu(x)^2

    @staticmethod
    def backward(ctx, grad_output):       # 反向：d/dx (relu(x)^2) = 2*relu(x)
        (x,) = ctx.saved_tensors
        return grad_output * 2 * x.clamp(min=0)

def relu_squared(x):
    return ReLUSquared.apply(x)           # 用 .apply 触发

x = torch.tensor([-1.0, 2.0], requires_grad=True)
y = relu_squared(x)
y.sum().backward()
print("x:", x.tolist(), "grad:", x.grad.tolist())   # grad = [0, 4]
```

运行：`python 20_custom_op_demo.py`。

## 1. 一句话直觉

> **自定义算子 = "给 torch 的 dispatcher 报个户口"。`define` 是登记名字和签名（schema），`impl` 是登记"各设备上怎么实现"，`register_fake` 是登记"不真算、只推形状"，自定义 `Function` 是登记"前向和后向的梯度公式"。**

类比：`dispatcher` 像**调度中心**——你打电话（`torch.ops.mylib.add`）报一个任务名，调度中心按"任务名 + 设备类型"查表，派给对应工人（impl）。`register_fake` 像"先报个虚拟尺寸"——让调度中心在"不动真格"（meta 模式）时也能知道结果长什么样，供 `torch.compile` 提前规划。

---

## 2. 核心原理

### 2.1 为什么需要自定义算子

torch 的算子虽然多，但**组合式**代码（比如你 `fused_ffn` 里的 `gate * up` 再 `@ w_down`）会**拆成多个 kernel**，每个 kernel 之间要读写显存（memory-bound 瓶颈）。自定义算子能：

1. **融合**：把多个操作合成一个 kernel，减少显存读写（你 `cuda_study` 里学的"访存优化四板斧"就是干这个）。
2. **用更优算法**：如 FlashAttention、PagedAttention，是标准算子库没有的。
3. **下沉到 CUDA/Triton**：绕过 Python 和部分 C++ 开销。

**你的项目定位**：`backend.py` 的 `TorchBackend` 是"组合式"参考实现，`cuda_ext` 是"下沉式"高性能实现——**两者通过 `Backend` 接口切换**，这正是第 17 篇策略模式 + 本篇自定义算子的完美配合。

### 2.2 dispatcher 的三层注册

```cpp
// 你的 bindings.cpp 已经在做的事（C++ 侧）：
TORCH_LIBRARY(kernels, m) {           // ① define：登记 schema
    m.def("vector_add(Tensor a, Tensor b) -> Tensor");
}
TORCH_LIBRARY_IMPL(kernels, CUDA, m) { // ② impl：登记 CUDA 设备实现
    m.impl("vector_add", &vector_add);
}
```

| 层 | 作用 | 你的 bindings.cpp |
|----|------|------------------|
| `define`（schema） | 登记名字 + 类型签名 | ✅ `m.def(...)` |
| `impl`（dispatch key） | 按设备登记实现 | ✅ `m.impl(...)` |
| `register_fake`（meta） | 不真算，只推形状 | ❌ **缺** |

**dispatch key**：`CUDA`/`CPU`/`Autograd`/`Meta` 等。dispatcher 按"张量的设备 + 当前模式"选 key。**`Autograd` key 专门处理梯度**（见 2.4），`Meta` key 专门给 meta tensor 推形状。

### 2.3 `register_fake`：为什么是工业级标配

**meta tensor** 是一种"只有形状、没有数据"的假张量（`device="meta"`）。它的用途：**在不动真数据、不占显存的前提下，跑通整个计算图、推导所有中间形状**。

`register_fake` 让你的算子在 meta 模式下也能"给出正确形状"：

```python
@torch.library.register_fake("mylib::add")
def _(x, y):
    return torch.empty_like(x)      # 形状和 x 一样，但不真算
```

**为什么必须**：
1. **`torch.compile` 依赖它**：compile 时用 meta tensor 走一遍图、推导形状，你的算子没 register_fake 就会在图里"断裂"，compile 失败或回退。
2. **`torch.export` / 模型导出依赖它**：导出 ONNX、TorchScript 时也要 meta 推导。
3. **形状检查**：不占显存地验证"算子对任意输入形状是否正确"。

> **这是你 `bindings.cpp` 现在缺的一环**。你注释里写了"在 Python 侧给它写一个 register_fake(形状推导)"——说明你已经有这个意识，只是还没落地。本篇就是把它做实。

### 2.4 自定义 autograd：`torch.autograd.Function`

对于**参与训练**的算子，只写前向不够，还要写**反向梯度**：

```python
class MyOp(torch.autograd.Function):
    @staticmethod
    def forward(ctx, x):            # 前向
        ctx.save_for_backward(x)    # 保存反向需要的输入
        return x ** 2

    @staticmethod
    def backward(ctx, grad_output): # 反向：链式法则
        (x,) = ctx.saved_tensors
        return grad_output * 2 * x  # d(x^2)/dx = 2x
```

**关键点**：
- `ctx.save_for_backward` 保存前向输入，反向时取出。
- `backward` 接收"上游传来的梯度" `grad_output`，返回"对每个输入的梯度"。
- 用 `.apply(x)` 调用，而不是 `MyOp(x)`。

**但注意**：如果你的算子是**纯推理**（你的引擎大部分是推理），可以**不写 backward**，只要在 `no_grad` 下用、或明确告诉 torch 这个算子不需要梯度。**推理引擎的自定义算子（如 fused_ffn、PagedAttention）通常只写前向**；训练用的算子才必须写反向。

## 3. 深入细节：把自定义算子做"生产级"的清单

| 检查项 | 为什么 | 怎么做 |
|--------|--------|--------|
| **meta 安全** | torch.compile/export 需要 | `register_fake` |
| **dtype/device 处理** | 输入是 fp16/bf16/cuda 都要对 | 算子内按输入 dtype 分派 |
| **错误检查** | 坏输入早报错 | `TORCH_CHECK`（C++）/ 显式 raise |
| **非连续输入** | `view` 类输入可能非连续 | 算子开头 `.contiguous()` 或按 stride 处理 |
| **autograd 正确**（训练用） | 梯度错会毁掉训练 | 用 `gradcheck` 验证 |

**用 `torch.autograd.gradcheck` 验证反向正确性**：

```python
from torch.autograd import gradcheck
x = torch.randn(3, 4, dtype=torch.double, requires_grad=True)
print(gradcheck(relu_squared, (x,), eps=1e-6, atol=1e-4))   # True = 反向正确
```

**gradcheck 原理**：用**数值梯度**（微扰法）逼近解析梯度，两者对比，误差小于阈值即正确。**这是自定义 autograd 算子的"单元测试"**，你写反向后必跑。

## 5. 自测题

**Q1（概念）**：`define`、`impl`、`register_fake` 三者的职责分别是什么？dispatcher 靠什么决定调用哪个实现？

**Q2（应用）**：写出一个 `Square` 自定义算子（`torch.autograd.Function`），前向算 `x^2`，反向算 `2x * grad_output`，并用 `gradcheck` 验证。

**Q3（思考）**：为什么 `torch.compile` 需要你的算子有 `register_fake`？它在编译期用 meta tensor 做了什么，为什么缺了就会"图断裂"？

<details>
<summary>点击展开答案</summary>

**A1**：`define` 登记算子的**名字 + 类型签名**（schema）；`impl` 登记**某个 dispatch key（设备/模式）下的具体实现**；`register_fake` 登记 **meta 模式下的形状推导**（不真算）。dispatcher 靠**算子名 + dispatch key**（由张量的 device、dtype、以及当前是否在 autograd/meta 模式决定）查表，选中对应实现。

**A2**：
```python
class Square(torch.autograd.Function):
    @staticmethod
    def forward(ctx, x):
        ctx.save_for_backward(x)
        return x * x
    @staticmethod
    def backward(ctx, grad_output):
        (x,) = ctx.saved_tensors
        return grad_output * 2 * x

x = torch.randn(3, 4, dtype=torch.double, requires_grad=True)
from torch.autograd import gradcheck
print(gradcheck(Square.apply, (x,), eps=1e-6, atol=1e-4))   # True
```

**A3**：`torch.compile` 编译期会先用 **meta tensor**（只有形状、无数据）把整张计算图"空跑"一遍，推导每个节点的输出形状、做图优化、规划 kernel。如果你的自定义算子没有 `register_fake`，编译期走到这个算子时**无法推导它的输出形状**（因为 meta 模式下没有真实数据可算），图就在这里"断裂"——compile 只能回退（fallback）到 eager 或直接报错。`register_fake` 就是给编译期提供"这个算子的输出形状是什么"的答案，让图能完整走通。
</details>
