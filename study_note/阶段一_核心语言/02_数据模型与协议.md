## 0. 先跑起来

```python
# 02_protocol_demo.py
from contextlib import contextmanager

# ── 1. 魔法方法：让对象可打印、可比较、可求长 ──
class Token:
    def __init__(self, text: str, id_: int):
        self.text = text
        self.id_ = id_

    def __repr__(self):            # 给开发者/调试看：准确、无歧义
        return f"Token(text={self.text!r}, id={self.id_})"

    def __len__(self):             # 支持 len(token)
        return len(self.text)

    def __eq__(self, other):       # 支持 token == "hi"（值比较）
        if isinstance(other, Token):
            return self.id_ == other.id_
        return False

    def __hash__(self):            # 可哈希 → 能当 dict 的 key（定义 __eq__ 必须定义 __hash__）
        return hash(self.id_)

t = Token("hello", 5)
print(repr(t))          # Token(text='hello', id=5)
print(len(t))           # 5
print(t == Token("hello", 5))   # True
print(hash(t))

# ── 2. 迭代器协议：让对象能被 for 遍历 ──
class BlockTable:
    """逻辑块表，支持 for 遍历和下标访问（你 PagedAttention 里 block_table 的雏形）"""
    def __init__(self, phys_ids: list[int]):
        self._ids = phys_ids
        self._pos = 0

    def __iter__(self):           # for 循环第一步：拿到迭代器
        self._pos = 0
        return self

    def __next__(self):           # for 循环每步：取下一个，取完抛 StopIteration
        if self._pos >= len(self._ids):
            raise StopIteration
        v = self._ids[self._pos]
        self._pos += 1
        return v

    def __getitem__(self, i):     # 支持 bt[0]、bt[1:3] 切片
        return self._ids[i]

bt = BlockTable([7, 6, 5])
print("遍历:", [x for x in bt])   # [7, 6, 5]
print("下标:", bt[1])             # 6

# ── 3. 生成器：用 yield 偷懒地"生产"序列，省内存 ──
def token_ids(seq: str):
    for ch in seq:                # 每次只 yield 一个，不一次性构造整个 list
        yield ord(ch)

gen = token_ids("abc")
print(next(gen))                  # 97
print(list(gen))                  # [98, 99]  ← 从上次暂停处继续

# ── 4. 上下文管理器：with 自动管理"进入/退出" ──
class MemoryGuard:
    """模拟：进入时记录显存，退出时打印净增量（可用于定位显存泄漏）"""
    def __enter__(self):
        import torch
        self.before = torch.cuda.memory_allocated() if torch.cuda.is_available() else 0
        return self

    def __exit__(self, exc_type, exc, tb):
        import torch
        after = torch.cuda.memory_allocated() if torch.cuda.is_available() else 0
        print(f"显存净变化: {after - self.before} bytes")
        return False   # False = 不吞异常，异常继续向外抛

with MemoryGuard():
    pass   # 实际使用时把要测的算子放这里
```

运行：`python 02_protocol_demo.py`（最后一段需要 torch 的环境，没 GPU 也能跑，只是打印 0）。

## 1. 一句话直觉

> Python 的语法糖是**"协议 + 魔法方法"的翻译器**：`for x in obj` 会被翻译成"先调用 `obj.__iter__()` 拿迭代器，再反复调用 `__next__()`，直到抛 `StopIteration`"。

类比：**协议就像 USB 接口标准**。你的设备（自定义类）只要实现了"USB 协议"（魔法方法），就能插进任何 USB 插座（`for`/`with`/`in`/`+`）。Python 不关心你内部是什么，只关心你有没有实现这个接口——这叫**鸭子类型**（duck typing）："走起来像鸭子、叫起来像鸭子，那就是鸭子"。

## 2. 核心原理

### 2.1 魔法方法（dunder methods）一览

| 魔法方法 | 触发语法 | 典型用途 |
|---------|---------|---------|
| `__init__` | `obj = C(...)` | 初始化 |
| `__repr__` | `repr(obj)`、控制台显示 | 调试友好，**建议每个类都写** |
| `__str__` | `str(obj)`、`print` | 用户友好展示 |
| `__len__` | `len(obj)` | 容器长度 |
| `__getitem__` | `obj[i]`、`obj[a:b]` | 下标/切片/迭代 |
| `__setitem__` | `obj[i] = v` | 写入 |
| `__contains__` | `x in obj` | 成员判断 |
| `__eq__` / `__hash__` | `==` / `hash()` | 值比较 / 可哈希 |
| `__call__` | `obj(...)` | 让实例可调用（函数式对象） |
| `__iter__` / `__next__` | `for` / `next()` | 迭代器协议 |
| `__enter__` / `__exit__` | `with` | 上下文管理器 |
| `__add__` / `__mul__` 等 | `+` / `*` | 运算符重载 |

> 记忆锚点：**这些方法你从不用"直接调"，而是通过语法让 Python 帮你调**。你写 `len(t)`，Python 找 `t.__len__()`。这就是"数据模型"的全部秘密。

### 2.2 `__repr__` vs `__str__`：工业调试的第一生产力

```python
class C:
    def __repr__(self): return "C()  # 给开发者：放进交互式环境能看到"
    def __str__(self):  return "这是一个 C"  # 给用户：print 时友好

c = C()
print(repr(c))   # C()  # 给开发者：放进交互式环境能看到
print(str(c))    # 这是一个 C
```

**工业铁律**：`__repr__` 的目标是"**尽量无歧义、能还原对象关键状态**"，这样你在调试器/日志里看到的字符串能直接定位问题。你现在的类（`Sequence`、`BlockAllocator`）都没有 `__repr__`，打印出来是 `<__main__.Sequence object at 0x...>`——**对调试毫无帮助**。下一篇你就会给它们补上。

### 2.3 迭代器协议：`iterable` 和 `iterator` 是两个概念

```
可迭代对象 iterable：有 __iter__()，返回一个迭代器（如 list、dict、range、生成器）
迭代器 iterator  ：同时有 __iter__() 和 __next__()（如文件对象、生成器、map 对象）

关系：iter(iterable) -> iterator；next(iterator) -> 元素 or StopIteration
```

- **可迭代对象可以被 `for` 反复遍历**（每次 `__iter__` 都从头发一个迭代器）。
- **迭代器是一次性的**：走到头就没了。

```python
lst = [1, 2, 3]
for x in lst: print(x)   # 第一次，OK
for x in lst: print(x)   # 第二次，OK（list 是可迭代对象，不是迭代器）

it = iter(lst)
print(next(it))          # 1
print(list(it))          # [2, 3]  ← 迭代器被消耗掉了
print(list(it))          # []      ← 已经到头，再来是空的
```

**为什么设计成"两个概念"？** 分离了"**能遍历的数据**（iterable，可重复）和"**遍历进行到哪里的游标**"（iterator，有状态、一次性）。这让"同一个数据被多个 for 同时遍历"成为可能。

### 2.4 生成器：最省内存的迭代器

`yield` 把一个普通函数变成**生成器函数**，调用它不执行函数体，而是返回一个生成器对象；每 `next()` 一次，才执行到下一个 `yield` 并**暂停、保存现场**。

```python
def squares(n):
    for i in range(n):
        yield i * i          # 暂停并交出值，下次从这里继续

g = squares(10**9)           # 没算任何东西，也没占内存
print(next(g))               # 0
print(next(g))               # 1
```

对比：`[i*i for i in range(10**9)]` 会瞬间吃掉几十 GB 内存；`(i*i for i in range(10**9))`（生成器表达式）则**懒加载、零内存**。

> **工业价值**：在推理引擎里，token 流、逐 batch 的数据加载、逐块读取权重……**凡是"数据量大且只需逐个消费"的场景，一律用生成器**。你 `model.py` 里的 `get_batch` 如果改成生成器，就不会一次性构造所有 batch。

### 2.5 上下文管理器：`with` 的资源安全网

`with` 的翻译过程：

```python
with expr as x:
    body
# 等价于：
x = expr.__enter__()
try:
    body
finally:
    expr.__exit__(exc_type, exc_value, traceback)   # 无论是否异常，都会执行！
```

**核心价值：保证"退出时一定执行清理"**，即使 body 抛异常。典型场景：

- `with open(f) as f:` —— 自动关文件
- `with torch.no_grad():` —— 自动开关梯度（**你已经在用了！**）
- `with lock:` —— 自动加锁/解锁
- `with MemoryGuard():` —— 自动测量显存

`__exit__` 返回 `True` 表示"我吞掉这个异常"，返回 `False`（或 `None`）表示"异常继续向上抛"。**除非你真的要吞异常，否则返回 False**。

`@contextmanager` 装饰器能把"生成器"变"上下文管理器"，免去手写 `__enter__`/`__exit__`：

```python
from contextlib import contextmanager

@contextmanager
def timed(name: str):
    import time
    t0 = time.time()
    yield                 # yield 之前的代码 = __enter__；之后 = __exit__
    print(f"{name} 耗时 {time.time() - t0:.3f}s")

with timed("attention"):
    pass  # 你的算子
```

### 2.6 `__slots__`：省内存 + 防手滑

默认情况下，类的实例属性存在一个 `__dict__` 字典里（灵活但占内存）。`__slots__` 声明固定的属性集合，禁止运行时加新属性：

```python
class TensorRef:
    __slots__ = ("name", "shape", "dtype")   # 只有这三个属性，省掉 __dict__

    def __init__(self, name, shape, dtype):
        self.name = name
        self.shape = shape
        self.dtype = dtype

t = TensorRef("x", (2, 3), "float32")
# t.extra = 1   # AttributeError! 不能动态加属性了
```

**何时用**：当你会有**海量小对象**（比如一个请求要建几十万个"块元数据"对象），`__slots__` 能显著省内存、略提速。**不必默认加**——只有确认是内存瓶颈时才用（第 14 篇会教你如何测量）。

## 3. 深入细节：三个高频坑

### 坑 1：`__eq__` 之后 `__hash__` 会变 `None`

```python
class A:
    def __eq__(self, other): return True

a = A()
# hash(a)  # TypeError: unhashable —— 定义 __eq__ 时 Python 自动把 __hash__ 设为 None
```

如果你想让自定义对象能当 dict 的 key，必须**同时**定义 `__eq__` 和 `__hash__`，并保证"相等的对象哈希值也相等"。**最省事的方案**：用 `@dataclass(frozen=True)`（第 04 篇），它自动生成正确的 `__eq__` 和 `__hash__`。

### 坑 2：迭代器对象"自返回"，别把状态搞混

```python
class Bad:
    def __init__(self, n): self.i = 0; self.n = n
    def __iter__(self): return self      # 返回自己
    def __next__(self):
        self.i += 1
        if self.i > self.n: raise StopIteration
        return self.i

b = Bad(3)
for x in b: print(x)   # 1 2 3
for x in b: print(x)   # 什么都不打印！← 因为 b 是迭代器（自返回），已被耗尽
```

**教训**：如果对象是"一次性游标"（有状态），就别指望它能被 `for` 反复遍历。想要可重复遍历，`__iter__` 应该返回一个**新的**迭代器对象，而不是 `self`。

### 坑 3：`__exit__` 里吞异常要慎重

```python
def __exit__(self, exc_type, exc, tb):
    return True   # ⚠️ 这样会把 body 里的所有异常静默吞掉，调试噩梦！
```

**工业铁律**：上下文管理器**默认不吞异常**（返回 False）。只有像 `contextlib.suppress(某异常)` 这种**明确针对特定异常**的场景才吞。

## 5. 自测题

**Q1（概念）**：`for x in range(5)` 和 `for x in [0,1,2,3,4]` 背后的协议调用有何不同？`range` 是迭代器吗？

**Q2（应用）**：写一个 `__call__` 的实用例子：一个"带缓存的前向函数"类，第一次调用时计算并缓存结果，之后直接返回缓存。提示：用 `__call__` 让实例能像函数一样被 `model(x)` 调用。

**Q3（思考）**：为什么 `with torch.no_grad():` 能保证即使 `__exit__` 前代码抛异常，梯度状态也能恢复？这体现了上下文管理器的什么设计原则？

<details>
<summary>点击展开答案</summary>

**A1**：`for x in range(5)`：先调用 `range(5).__iter__()` 得到一个 `range_iterator`，再反复 `__next__()`。`range` **不是**迭代器（它没有 `__next__`，是 iterable），`iter(range(5))` 返回的 `range_iterator` 才是迭代器。`for x in [0,1,2,3,4]`：`list.__iter__()` 返回 `list_iterator`，再 `__next__()`。两者协议相同，只是迭代器具体类型不同；`range` 惰性不占内存，list 一次性占满。

**A2**（示例）：
```python
class CachedForward:
    def __init__(self, fn):
        self.fn = fn
        self._cache = {}
    def __call__(self, x):
        if x not in self._cache:
            self._cache[x] = self.fn(x)
        return self._cache[x]

f = CachedForward(lambda x: x * x)
print(f(3), f(3))   # 9 9，第二次命中缓存
```

**A3**：因为 `with` 被翻译成 `try/finally`，`__exit__` 在 `finally` 块里，**无论 body 正常结束还是抛异常都会执行**。这体现上下文管理器的核心设计原则：**把"资源的获取与释放"和"业务逻辑"分离，并用 finally 保证释放一定发生**——与 RAII（C++）异曲同工。
</details>
