## 0. 先跑起来

```python
# 06_collections_demo.py
from collections import defaultdict, Counter, deque
from functools import lru_cache, partial, reduce
from itertools import chain, islice, product, groupby
import heapq, bisect

# ── 1. defaultdict：访问不存在的 key 不报错，给默认值 ──
d = defaultdict(list)          # 默认值是空 list
d["a"].append(1)               # 不用先 if "a" not in d
print(d)                       # defaultdict(<class 'list'>, {'a': [1]})

# 典型：按 key 分组
pairs = [("ffn", 1), ("attn", 2), ("ffn", 3)]
groups = defaultdict(list)
for k, v in pairs:
    groups[k].append(v)
print(groups)                  # {'ffn': [1, 3], 'attn': [2]}

# ── 2. Counter：统计频次 ──
tokens = ["the", "a", "the", "model", "a", "the"]
cnt = Counter(tokens)
print(cnt)                     # Counter({'the': 3, 'a': 2, 'model': 1})
print(cnt.most_common(2))      # [('the', 3), ('a', 2)]  ← top-k 频次

# ── 3. deque：两端 O(1) 增删（list 头部插入是 O(n)） ──
q = deque(maxlen=3)            # 固定长度：满了自动挤出最旧的
for i in range(5):
    q.append(i)
print(list(q))                 # [2, 3, 4]  ← 天然"滑动窗口"

# ── 4. functools：lru_cache / partial / reduce ──
@lru_cache(maxsize=None)
def fib(n):                    # 无缓存是 O(2^n)，有缓存变 O(n)
    return n if n < 2 else fib(n - 1) + fib(n - 2)
print(fib(50))                 # 12586269025，瞬间出结果

def pow(base, exp): return base ** exp
square = partial(pow, exp=2)   # 固定参数，造新函数
print(square(5))               # 25

print(reduce(lambda a, b: a * b, [1, 2, 3, 4]))   # 24 ← 累积归约

# ── 5. itertools：惰性迭代工具箱 ──
print(list(chain([1, 2], [3, 4])))          # [1, 2, 3, 4] 连接
print(list(islice(range(100), 5, 10)))      # [5, 6, 7, 8, 9] 切片（惰性）
print(list(product("ab", [1, 2])))          # 笛卡尔积

# ── 6. heapq：堆（O(log n) 维护 top-k） ──
nums = [5, 1, 9, 3, 7]
print(heapq.nlargest(2, nums))              # [9, 7]  ← top-k 不用全排序
heap = []; 
for n in nums: heapq.heappush(heap, n)
print(heapq.heappop(heap))                  # 1  ← 依次弹出最小

# ── 7. bisect：有序列表的二分查找/插入 ──
arr = [1, 3, 5, 7, 9]
print(bisect.bisect_left(arr, 5))           # 2  ← 5 应插在索引 2
bisect.insort(arr, 6)                        # 保持有序地插入
print(arr)                                  # [1, 3, 5, 6, 7, 9]
```

运行：`python 06_collections_demo.py`。

## 1. 一句话直觉

> **选容器 = 选"存取方式"的复杂度契约；标准库算法 = 别人已经替你优化好的循环。**

类比：`list` 是"按门牌号找人的长走廊"（按下标 O(1)，但找"谁在走廊里"要挨个看 O(n)）；`dict/set` 是"哈希索引的档案柜"（查"在不在"O(1)）；`deque` 是"两头都能开门的车厢"；`heapq` 是"自动保持最小的那一个总在最上面的自动分拣机"。

## 2. 核心原理

### 2.1 内置容器复杂度速查表（面试必背）

| 操作 | list | dict | set | deque |
|------|------|------|-----|-------|
| 按下标访问 `x[i]` | O(1) | — | — | O(1) 两端 |
| 判断存在 `in` | O(n) | O(1) | O(1) | O(n) |
| 末尾增 `append` | O(1)* | — | — | O(1) |
| 头部增/删 | O(n) | — | — | **O(1)** |
| 插入/删除中间 | O(n) | O(1) | O(1) | O(n) |
| 查 key `x[k]` | — | O(1) | — | — |
| 遍历 | O(n) | O(n) | O(n) | O(n) |

> *list 的 `append` 是"均摊 O(1)"：偶尔扩容会 O(n)，平均下来是 O(1)。

**决策口诀**：
- **要按下标/顺序 + 常改尾部** → `list`
- **要"查是否存在 / 去重 / 集合运算"** → `set`
- **要"键值映射 / 按 key 快速查"** → `dict`
- **要"两头增删 / 固定长度滑动窗口"** → `deque`
- **要"不可变、可哈希、当 dict key"** → `tuple`/`frozenset`

### 2.2 为什么"选对容器"能差一个数量级

```python
# 反例：用 list 做成员判断（O(n)）
tokens_in_vocab = list(range(100000))       # 假装是词表 id
target = 99999
print(target in tokens_in_vocab)            # O(n)：最多扫 10 万次

# 正例：用 set 做成员判断（O(1)）
vocab_set = set(tokens_in_vocab)
print(target in vocab_set)                  # O(1)：哈希一下直接定位
```

你的引擎里，如果"判断某个 token 是否在词表""判断某个物理块是否已分配"这类**高频成员判断**用了 list，每次推理都在白白做 O(n) 扫描。用 `set` 是零成本优化。

### 2.3 `defaultdict` / `Counter` / `deque` 的具体用法

**`defaultdict`**：省掉"先判 key 存在"的样板。

```python
# 旧：
d = {}
for k, v in pairs:
    if k not in d: d[k] = []
    d[k].append(v)

# 新：
d = defaultdict(list)
for k, v in pairs: d[k].append(v)
```

**`Counter`**：统计 + top-k 频次一步到位（`most_common`）。

**`deque(maxlen=N)`**：固定长度队列，天然滑动窗口（比如记录"最近 N 个 token 的生成耗时"做监控）。

### 2.4 `functools.lru_cache`：纯函数结果缓存

```python
@lru_cache(maxsize=None)
def rope_freqs(head_dim, max_len): ...   # 昂贵的 RoPE 因子计算只算一次
```

**原理**：以"参数"为 key 缓存返回值；相同参数再调，直接命中缓存返回，不重算。**前提：函数必须是纯函数**（同参同结果、无副作用），且参数可哈希。

> 你 `model.py` 的 `precompute_freqs_cis` 就是理想的 `lru_cache` 目标（第 03 篇提过）。缓存命中时，省下的是整个三角函数的批量计算。

### 2.5 `heapq`：top-k 与优先队列

**top-k 不用全排序**：`heapq.nlargest(k, nums)` 内部用堆维护，复杂度 O(n log k)，比 `sorted(nums)[-k:]` 的 O(n log n) 更优（当 k ≪ n 时）。

**优先队列**（工业常见：任务调度、请求按优先级处理）：

```python
import heapq
tasks = []                        # (优先级, 序号, 任务) —— 序号用于优先级相同时保序
heapq.heappush(tasks, (1, 0, "低优先"))
heapq.heappush(tasks, (0, 1, "高优先"))
while tasks:
    print(heapq.heappop(tasks)[2])    # 总是先弹优先级最高的（数字小=高优先）
```

> 你的 `temp_topk` 目前用 `torch.topk`（GPU 张量版，对的对 GPU 就该用它）；但如果你要在 **CPU 侧的调度器**里做"按剩余长度选请求"的优先队列（第 23 篇 continuous batching 会用到），`heapq` 就是标准答案。

### 2.6 `bisect`：维护"有序列表"

当数据**需要保持有序、又频繁二分查找/插入**时，`bisect` 比"每次 sort"高效：

```python
sorted_block_ids = [3, 5, 8]
bisect.insort(sorted_block_ids, 6)      # 插入后仍有序 [3, 5, 6, 8]
i = bisect.bisect_left(sorted_block_ids, 6)   # 二分定位
```

### 2.7 `itertools`：声明式迭代，少写循环

| 函数 | 作用 | 替代的手写循环 |
|------|------|---------------|
| `chain(a, b)` | 连接多个可迭代 | `for x in a: yield x; for x in b: yield x` |
| `islice(it, s, e)` | 惰性切片 | 手动计数 break |
| `product(A, B)` | 笛卡尔积 | 双层嵌套循环 |
| `permutations/combinations` | 排列/组合 | 复杂递归 |
| `groupby(it, key)` | 相邻分组 | 手动状态机 |
| `zip_longest(a, b)` | 等长之外的对齐 | 处理长度不等 |

> 工业价值：这些是**惰性生成器**，不一次性构造结果，省内存。你扫描 batch、生成所有 (block, offset) 组合时，`product` + `chain` 能省掉大量手写循环。

## 3. 深入细节：三个高频坑

### 坑 1：dict 遍历中修改会报错

```python
d = {"a": 1, "b": 2}
for k in d:
    del d[k]          # RuntimeError: dictionary changed size during iteration
```

**解法**：遍历一个"快照"——`for k in list(d.keys()):` 或先收集要删的 key 再删。

### 坑 2：`sort(key=)` 比 `cmp` 快且清晰

```python
# 按"隐藏维大小"排序，key 只算一次
models.sort(key=lambda m: m.hidden_dim)

# 多级排序：先按 a，再按 b
items.sort(key=lambda x: (x.a, x.b))
```

Python 3 移除了 `cmp` 参数（只留 `key`）。**`key` 函数每个元素只算一次**，而老式 `cmp` 每次比较都算，性能差很多。**排序是稳定的**（相等元素保持原顺序），这让你能"先按次要 key 排、再按主要 key 排"实现多级排序。

### 坑 3：`lru_cache` 会"涨内存"，别用在参数空间无限的地方

```python
@lru_cache(maxsize=None)
def f(x: str): ...   # 若 x 是"永不重复的用户输入"，缓存会无限膨胀
```

**对策**：给 `maxsize` 设个有界值（如 128/1024），或用 `@cache` 时明确"参数空间有限"。缓存"参数空间有限且重复率高"的纯函数才划算。

## 5. 自测题

**Q1（概念）**：为什么 `x in list` 是 O(n) 而 `x in set` 是 O(1)？各自的底层数据结构是什么？

**Q2（应用）**：实现"取列表中最大的 3 个数"，分别用 `sorted` 和 `heapq.nlargest`，并说明当列表有 100 万个数时哪个更快、为什么。

**Q3（思考）**：你的推理引擎要做"根据请求的剩余 token 数，每次挑剩余最少的请求先算"（最短作业优先调度）。用什么数据结构最合适？给出伪代码。

<details>
<summary>点击展开答案</summary>

**A1**：`list` 是连续数组，`in` 只能从前往后线性扫描比较，最坏 O(n)；`set`/`dict` 底层是**哈希表**，`in` 先算哈希值直接定位桶，平均 O(1)。代价是 `set` 无序、不可重复、多占内存。

**A2**：`heapq.nlargest(3, nums)` 更快。`sorted` 是 O(n log n) 全排序（对 100 万元素代价巨大）；`nlargest` 用大小 3 的堆维护，是 O(n log 3) ≈ O(n)，当 k ≪ n 时显著更快。

**A3**：用**最小堆（heapq）**维护请求的剩余长度。伪代码：
```python
import heapq
waiting = []   # (剩余长度, 请求id, 请求对象)
def add(req): heapq.heappush(waiting, (req.remaining, req.id, req))
def next_req(): return heapq.heappop(waiting)[2]   # 总是弹出剩余最少的
```
每次取最短作业 O(log n)，插入 O(log n)，比"每次全量扫描找最小"的 O(n) 高效得多。
